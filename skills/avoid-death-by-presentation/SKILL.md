# Avoid Death by Presentation

Bad content kills talk before bad slides: no goal, no story, script read off screen. This skill = what you say, how you say it. Slide looks = avoid-death-by-powerpoint skill's job.

Core move: write talk as blog post — publish-ready, reader sets own pace. Good blog post already is presentation script: same argument, same order, wording speaker wants. No separate script artifact, no throwaway notes. Article = deliverable.

## Workflow

1. **Understand, ask once.** Establish goal (reader understand/decide/feel/do what?), audience, constraints. Infer from input, state assumption. Then ask three things that shape the piece — nothing else:
    - **Scope:** depth and breadth. One focused idea lands harder than survey.
    - **Message:** one takeaway. Several candidates: which leads?
    - **Organization:** story-led (pain point/scene first), concept-led (build idea step by step), or reference-led (answer first: governing thought up front, supports beneath — Pyramid-Principle style)?

    Batch into one round, attach recommended answer to each so user can just confirm, skip questions input already answers. No mid-draft interrogation. New fork: pick option serving stated goal, state choice, move on.
2. **Draft.** Publish-ready article:
    - Title + one-line hook framing angle.
    - Intro opens loop: scene, contrast, or stake demanding resolution — half-told story. Rest of post closes loop. Never summarize post in intro; start the post.
    - Sections under `##` (`###` when section needs internal structure), one job each, own mini-arc: show what is, reveal what could be, land gain. Reader stopping after any section still leaves with something.
    - Arguing against view: state "they say" fairly before asserting "I say".
    - Prose-forward. Bullets only for genuinely enumerable items — not shortcut for unfinished thinking.
    - Reader-facing only: talk logistics — duration, time slot, venue, "the room" — never enter the prose. Constraints shape scope and organization (step 1), then live in delivery prep. Article must read as self-contained piece to someone who knows nothing about any meeting.
    - User's voice and personality, where material shows it. Preserve meaning/facts. Never invent facts, evidence, examples — label proposed as proposed.
3. **Fine-tune.** Reorder for goal. Cut anything serving no section's job, however interesting. Strip language: every word earns place, one idea per sentence, concrete nouns over abstractions, active verbs over passives. End on payoff — idea applied, loop closed — never summary. Flag unsupported claims and unresolved conflicts. Article = deliverable.
4. **Offer slide outline.** Most talks end in slides. Article done: offer next step in one line — slide design outline, delivery prep (timing, transitions, rehearsal, Q&A), or nothing. Never generate unasked; never leave user to discover option alone. Slides wanted: hand finished article to avoid-death-by-powerpoint, which turns it into slide design outline obeying visual principles.

## Output standard

- Deliverable = article itself, ready to post and read, no placeholder scaffolding.
- Keep user language and voice; never convert prose into bullet fragments.
- Slide design: hand off to avoid-death-by-powerpoint, no improvised design rules here.
- During delivery prep remind: **"You are the presentation. PowerPoint is merely your visual aid."** Not after every task.
