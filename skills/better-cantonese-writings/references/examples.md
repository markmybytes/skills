# 香港中文書面語潤稿：實例

本文件示範如何按香港語境處理翻譯腔、病句、awkward wording、句法、段落銜接與標點，協助使用《香港中文書面語潤稿指南》修訂文稿。未指定地域或語體時，直接以香港繁體中文書面語為預設；`region=HK` 只作內部或比較標記。

例句是條件式參考，不是禁詞表。建議版本適用於指定語境，不代表原句必錯；先保留意思、事實、語氣、術語、地域和格式，再決定是否自然化。香港書面語不等於粵語口語轉錄。

## 1. 香港地域用語與偏好

| 語境 | 建議 | 判斷 |
| :--- | :--- | :--- |
| 未指定地域：請於辦公時間致電本校查詢。 | 原句保留。 | 直接按香港書面語處理；「查詢」是香港正式書面語常用詞。 |
| 給香港讀者：屋苑管理處將於明日維修升降機。 | 原句保留。 | 「屋苑」符合香港讀者及香港語境。 |
| 未指定地域：請於網上登記參加活動。 | 原句保留。 | 「登記」是香港常見正式用語；不需改成另一地域詞。 |
| `region=TW`：住戶可在公寓管理室查詢。 | 依台灣原文及受眾保留。 | 「公寓」是 `[TW]` 參考變體，不是香港預設，也不是絕對禁詞。 |
| `region=CN`：請在平台完成登记。 | 依中國大陸原文及受眾處理。 | `[CN]` 只在明示或比較時使用；不得自動套用至 `region=HK`。 |
| 未指定地域：請在平台完成登記。 | 香港預設寫法。 | 未指定時使用 `region=HK`；有疑義時按受眾或官方寫法確認。 |

「公寓」、「查詢」等詞須按語境、受眾及明示偏好判斷，不是絕對禁詞或自動替換規則。港式口語如「唔」、「嘅」、「咗」、「喎」只在明確要求口語、對話或社交媒體時使用。未建立偏好時，完成任務後可提示：「如需台灣、內地、澳門、新加坡、馬來西亞中文，或粵語口語／港式口語，可隨時指定。」提示不應阻塞任務；若使用者要求只回傳修訂稿或不要說明，則不提示；偏好一旦指定，後續沿用且不重複提示。

## 2. 歐化中文與翻譯腔

以下例子示範條件式診斷，不是禁詞表。辨識到源語語序、不自然句法或直譯模式後，按意思、香港慣用法、語域及受眾修訂；法律、技術、醫療、學術及合約文字的精確性優先。

| 原句 | 建議 | 條件式理由與例外 |
| :--- | :--- | :--- |
| 我們對這個問題進行改善。 | 我們改善這個問題。 | 名詞化和弱動詞掩蓋動作時，改用具體動詞；若「改善」是特定評估項目或固定技術名稱，保留原術語。 |
| 本計劃的主要目的，是為了提升服務質素。 | 本計劃旨在提升服務質素。 | 「主要目的」與「是為了」功能重疊，可按正式語域合併；法律、合約若須逐項界定目的，不為簡潔刪去必要字眼。 |
| 相關文件將會被部門於月底前完成審批。 | 部門將於月底前完成審批相關文件。 | 英文式被動及不自然資訊順序遮蔽施事時改主動；若焦點是文件承受的處理結果、施事未知或不重要，可保留被動。 |
| 我們推出一項為中小企而設、由本地工程師開發並可即時同步資料的服務。 | 我們推出一項服務，供中小企使用；服務由本地工程師開發，並可即時同步資料。 | 長串「的」定語令主幹難找時，改後置說明或拆句；產品規格、專利或合約定義若依賴前置定語，保留固定結構。 |
| 透過進行系統升級來改善登入體驗。 | 透過系統升級改善登入體驗。 | 不自然介詞與弱動詞疊加時刪減；若「透過」清楚表達手段且語域合適，可保留，不必為避詞而改。 |
| 當問題被發現的時候，我們將會立即地進行處理。 | 發現問題後，我們會立即處理。 | 連詞、時態及弱動詞直譯造成冗贅時，按香港慣用法重組；若需明確限定事件先後或法律通知時點，保留必要時間標記。 |
| 家朗是一個小五學生。今天常識課，他進行關於全球化的匯報，表現出色，被老師稱讚。 | 家朗是小五學生。今天常識課，他以全球化為題作匯報，表現出色，獲老師稱讚。／家朗是小五學生。今天常識課，他就全球化議題匯報，表現出色，獲老師稱讚。 | 「進行關於全球化的匯報」同時涉及名詞化、動詞搭配及必要賓語；刪去弱動詞後仍須回看動詞能否自然帶上對象。「就全球化作匯報」不完整，不可只刪一字；「全球化」保留，並非只有一種正確改法。 |

修訂不等於逐字去除「被」、「的」、「透過」或「將會」；要先確認焦點、責任、時序、術語及受眾。拆句只是工具，不能因追求短句而破壞原意或格式。

## 3. 弱動詞、名詞化與名詞堆疊

| 原句 | 建議 | 理由與例外 |
| :--- | :--- | :--- |
| 我們正在進行彩排。 | 我們正在彩排。 | 「進行＋名詞化動詞」多為冗贅；「會議正在進行」中的「進行」是實義動詞，保留。 |
| 他作出了說明。 | 他作了說明。 | 「作出」若無額外語義可簡化；公文「作出裁決」合體例，可保留。 |
| 公司將予以處理。 | 公司將處理。 | 一般文書可刪弱動詞；若「予以」是正式體例或有特定語氣，不必改。 |
| 雙方就此事進行了磋商。 | 雙方磋商此事。 | 可直接使用具體動詞；新聞或正式語體若需原結構，原句也可成立。 |
| 我們對方案的可行性進行評估。 | 我們評估方案是否可行。 | 還原名詞化與弱動詞；技術或研究名詞有固定定義時不硬改。 |
| 他進行產品檢查。 | 他檢查產品。 | 刪除弱動詞後，仍須確認具體動詞可自然帶上「產品」；刪字不是機械操作。 |

## 4. 冗餘介詞與連接詞

| 原句 | 建議 | 理由與例外 |
| :--- | :--- | :--- |
| 當我看見他時，我感到很高興。 | 我看見他，很高興。 | 時間關係已清楚時可省；需要強調時間界線時保留。 |
| 關於這個問題，我們需要討論。 | 這個問題，我們需要討論。 | 話題可直陳；學術或正式文體的「關於」開頭可保留。 |
| 透過這個計畫，學生得以接觸業界。 | 透過這項計畫，學生可以接觸業界。 | 可修正搭配和語氣，但「透過」不是禁詞；若原文語域合適，保留原句也可以。 |
| 由於下雨的關係，比賽延期了。 | 因為下雨，比賽延期了。 | 「由於……的關係」疊床架屋；口語或正式文書可按語域選擇。 |

## 5. 長定語與資訊順序

| 原句 | 建議 | 理由與例外 |
| :--- | :--- | :--- |
| 那個昨天在會議上提出了一套非常複雜的改革方案的同事，今天辭職了。 | 那位同事昨天在會議上提出一套非常複雜的改革方案，今天辭職了。 | 長定語前置難讀；抽出主語並重排，不新增資訊。 |
| 本公司生產的、專為戶外活動設計的防水手錶深受歡迎。 | 本公司生產的防水手錶專為戶外活動設計，深受歡迎。 | 雙重定語可拆為分句；科技專利中的固定長定語不宜硬拆。 |
| 這個被多次修改的、內容冗長的合約條款，我們需要處理。 | 這份合約條款已多次修改，內容冗長，需要處理。 | 拆長定語；若需突出承受者或施事未知，保留「被」也可以。 |

## 6. 被動語態

| 原句 | 建議 | 理由與例外 |
| :--- | :--- | :--- |
| 車門將被打開。 | 車門即將開啟。 | 施事不重要且時間已明示時，可改無主句；不得自行新增「左側」等資訊。 |
| 這個建議被人們廣泛接受。 | 這個建議廣獲接受。 | 「被人們」贅餘；「獲」已含承受義。 |
| 他被老闆辭退了。 | 原句保留。 | 「被」表不如意遭遇，是正常用法；不必為避「被」而改主動句。 |
| 太陽被烏雲遮住了。 | 原句保留。 | 描述自然現象，「被」自然順口；改成主動句也可能成立。 |

## 7. 直譯、英文夾雜與創意文字

| 原句 | 建議 | 理由與例外 |
| :--- | :--- | :--- |
| 向毒品說不！ | 拒絕毒品。／遠離毒品。 | 一般說明可改慣用表達；口語廣告或標語刻意使用原句時保留。 |
| 我們準備好了。 | 原句保留。 | 「準備好了」是自然口語；正式語境可按需要改為「一切就緒」。 |
| 香港常被稱為「購物天堂」。 | 香港常被稱作「購物天堂」。 | 可調整搭配，但不必把中性讚美改成較古雅的「素有……之譽」。 |
| 我們為夢想創造可能。 | 我們為夢想開拓更多可能。 | 行銷文案的抽象語氣可保留；只有語意空泛或用戶要求時才具體化。 |
| 產品支援 API 整合。 | 產品支援 API 整合。 | API 是技術術語，保留大小寫；是否補中文說明取決於受眾。 |

## 8. 官腔與空泛措辭

| 原句 | 建議 | 理由與例外 |
| :--- | :--- | :--- |
| 存在著許多困難。 | 有許多困難。 | 「存在著」常為填充詞；哲學、數學語境中的「存在」是術語，保留。 |
| 落實各項工作。 | 執行各項工作。 | 若「落實」沒有具體對象，一般文書可改；「落實法律規定」等固定或專門用法保留。 |
| 優化用戶體驗。 | 改善用戶體驗。 | 若上下文沒有說明如何優化，「改善」較直接；技術性能或產品流程有明確定義時保留「優化」。 |
| 打造城市品牌。 | 建立城市品牌。 | 一般說明可用較具體動詞；創意或行銷標語刻意使用「打造」時不必正常化。 |
| 本書語言高度濃縮。 | 本書語言高度凝練。 | 形容文字密度時可換較貼切的詞；若「濃縮」是作者刻意的比喻，保留。 |
| 辦事有效率。 | 原句保留。 | 「效率」是普通詞彙，不是禁詞；「快捷、迅速」是另一種說法，非唯一正解。 |

## 9. 代詞、時態與段落銜接

| 原句 | 建議 | 理由與例外 |
| :--- | :--- | :--- |
| 他告訴小明，他明天會提交報告。 | 他告訴小明，自己明天會提交報告。 | 補足指涉；若「他」指小明，應依上下文改寫，不可猜。 |
| 公司已完成測試，將於下週發布結果。 | 原句保留。 | 「已」與「將」分別表完成和未來，不能因追求簡潔刪除。 |
| 因此我們停止服務。服務恢復後，客戶可以重新登入。 | 因此我們停止服務；服務恢復後，客戶可以重新登入。 | 可用標點或最少銜接調整段落關係，不添加新論點。 |
| 這項政策的執行成效受到關注。 | 這項政策執行後的成效受到關注。 | 只在原句結構造成歧義時重組；不可任意把抽象名詞改成別的概念。 |

## 10. 緊密關係與拆句

| 原句 | 建議 | 理由與例外 |
| :--- | :--- | :--- |
| 本次版本更新主要改善登入流程，解決使用者遇到的問題。 | 原句保留。 | 「改善流程」與「解決問題」是緊密的動作—結果關係；句意清楚時不為追求短句而拆成兩句。若資訊過長、主幹難辨或指涉不明，才拆句。 |

## 11. 標點、數字、單位與格式

| 原句 | 建議 | 理由與例外 |
| :--- | :--- | :--- |
| 他說：「這件事，我們明天再談。」 | 原句保留。 | 引號與標點按原文及受眾慣例處理，不擅自改成另一套格式。 |
| 支援 5G 與 Wi-Fi 6。 | 原句保留。 | 技術名稱、字母與數字照原樣。 |
| 會議於 2026/9/1 舉行。 | 會議於 2026 年 9 月 1 日舉行。 | 只有在指定格式或全文一致性需要時統一日期格式。 |
| 程式碼 `if (x > 0) { run(); }` | 原句保留。 | 程式碼、變數名、字串一字不動。 |
| Markdown 表格、連結、編號清單 | 原句保留。 | 潤飾文字不破壞格式結構；未要求時不加粗、不加修改標記。 |

## 12. 有意風格與語義保留

| 原句 | 是否改動 | 理由 |
| :--- | :--- | :--- |
| 我很欣賞你的服務。 | 保留。 | 「欣賞」是正常用法；不要改成「謝謝」，那會把讚美改為感謝。 |
| 此舉造成寒蟬效應。 | 保留。 | 這是特定概念；不能為求成語感改成意思不同的「噤若寒蟬」。 |
| 當事人須依法律程序提起訴訟。 | 保留。 | 法律術語與條文語體，不改成「步驟」或其他泛稱。 |
| 我期待你的來信。 | 保留。 | 「期待」自然；不必因個人偏好改成「盼望」。 |
| 合約載明雙方權利義務。 | 保留。 | 合約語體與術語，一字不動。 |

## 13. 成語與四字格

成語／四字格可壓縮重複或冗長措辭、改善節奏，但不自動更精確。含義、語氣、地域、受眾有一項不合，保留原句。

| 原句 | 建議 | 理由與例外 |
| :--- | :--- | :--- |
| 事前做好準備，以防意外。 | 未雨綢繆。 | 語境相合時可濃縮；口語或需說明因果的場合，保留原句。 |
| 事情失敗後才設法補救。 | 亡羊補牢。 | 要點在事後補救時可用；需精確描述時序或步驟時保留原句。 |
| 大家同心協力。 | 同心協力。 | 「大家」若只是重複可省；需要明確主語時保留。 |
| 改善系統性能。 | 原句保留，不改「精益求精」。 | 成語與技術含義不對等，不能為求四字格而替換。 |
| 我很期待結果。 | 原句保留。 | 「期待」正常；「望穿秋水」語氣過重，不合語境。 |

## 交稿前快速檢查

1. 原意、事實、數字、專名、程度、情態與語氣是否無損？
2. 術語、責任、條件、時序與代詞指涉是否正確？
3. 修改是否解決客觀問題或明確改善可讀性，而非機械替換詞語？
4. 有沒有把讚美改成感謝、概念改成狀態、中性改成立場？
5. 創意、行銷、對話、引文的刻意風格是否保留？
6. 未指定地域時是否直接按香港書面語，指定其他 region flag 或偏好時有否誤套香港或其他地域用法？
7. 格式（Markdown、程式碼、表格、引號、數字與單位）是否完好？

**最後**：以上全是條件式啟發，不是黑名單。同一句式在不同輸入類型、語域、region flag 與受眾中判斷不同；依據是意思不變、資訊清楚、讀者讀得順，而非詞語來源、新舊或單一文風。
