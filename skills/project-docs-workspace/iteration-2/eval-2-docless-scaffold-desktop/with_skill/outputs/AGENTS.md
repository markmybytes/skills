# AGENTS.md

install-it is a Windows desktop application (Wails v2 + Go backend, Vue 3
frontend) for organizing and running driver/software installers, with automatic
hardware-based selection.

## Documentation map

| Doc                                | Read when           | Purpose / ownership                 |

## Overview

- **Entry:** `main.go` — Wails app bootstrap, binding registration, and runtime
  layout setup.
- **Run:** `wails dev` from the repository root (builds the frontend, then
  starts the app).
- **Runtime layout:** the app creates `conf/` (SQLite DB `data.db`, settings
  file `setting.json`) and `drivers/` (`network`, `display`, `miscellaneous`)
  next to the executable.

## Tech Stack

- **Go:** 1.25 — Wails v2 backend; module `install-it`.
- **Frontend:** Vue 3, Vite, TypeScript, Pinia, vue-i18n (en + zh-Hant-HK),
  Nuxt UI, Tailwind CSS — in `frontend/`.
- **Database:** SQLite via `glebarez/sqlite`, GORM with gormigrate migrations.
- **Platform:** Windows is the target — WMI queries (`pkg/sysinfo`), registry,
  and the PawnIO driver (`pkg/cputemp`); a few non-Windows build files exist
  for portability.
- **Node:** 24 (see `frontend/package.json` `volta`).

## Repository Map

- `main.go`, `app.go` — app bootstrap and Wails-bound `App` methods (paths,
  file dialogs, WebView2, version).
- `pkg/storage/` — SQLite/GORM storage: driver groups, drivers, rule sets, app
  settings.
- `pkg/matching/` — evaluates match rules against live hardware (WMI).
- `pkg/execute/` — command execution engine (run, abort, output capture).
- `pkg/porter/` — import/export of settings and data (ZIP with manifest,
  backup and rollback).
- `pkg/update/` — update check (GitHub Releases) and staged in-place updates.
- `pkg/sysinfo/` — WMI hardware/OS info; PCI ID database via `go generate`.
- `pkg/cputemp/` — CPU temperature via PawnIO driver (Windows only).
- `pkg/status/`, `pkg/errcode/`, `pkg/utils/` — shared statuses, error codes,
  and helpers.
- `frontend/src/` — Vue app: `pages/`, `components/`, `composables/`,
  `stores/`, `i18n/`, `utils/`, `router/`, `types/`, `__tests__/`.
- `frontend/wailsjs/` — generated Wails bindings; do not hand-edit
  (regenerated by `wails dev` / `wails build`).
- `build/` — Wails build output (generated).
- `pkg/**/*_test.go` — Go unit and fuzz tests beside each package.
- `frontend/src/__tests__/` — Vitest unit tests.

## Commands

Run from the repository root unless noted. Apply fixes before verification.

| Scope                        | Fix                                     | Verify                    |
| ---------------------------- | --------------------------------------- | ------------------------- |
| Backend                      | `go build ./...`                        | `go test ./pkg/...`       |
| Frontend (in `frontend/`)    | `npm run lint`, `npm run format`        | `npm test`                |
| Frontend build (in `frontend/`) | `npm run build`                      | `npm run type-check`      |
| PCI ID database              | `go generate ./pkg/sysinfo/...`         | (regenerated before tests in CI) |
| App build                    | `wails build`                           | run `build/bin/install-it.exe` |

- `go generate ./pkg/sysinfo/...` regenerates the compressed PCI ID database
  used for hardware name resolution; CI runs it before `go test`.
- The production binary version is injected with
  `wails build -ldflags "-X main.buildVersion=<version>"`.
- Backend errors are string codes (e.g. `errStorageNotFound`) defined in
  `pkg/errcode` and translated in `frontend/src/i18n/`; keep them in sync.

## Testing

- **Go:** `go test ./pkg/...` — unit and fuzz tests beside each package
  (e.g. `pkg/update/integration_test.go`); root `App` tests in `app_test.go`.
- **Frontend:** Vitest + jsdom, suites in `frontend/src/__tests__/`
  (components, stores, utils, i18n completeness); run `npm test` in
  `frontend/`.
- **CI:** GitHub Actions. `test.yml` runs Go tests on `windows-latest` and
  frontend tests on `ubuntu-latest` for PRs to `main`;
  `build_and_release.yml` builds Windows x86/x64 artifacts and creates a GitHub
  release on `v*` tags.
- **Fixtures/mocks:** `frontend/src/__tests__/setup.ts` configures the Vitest
  environment; backend tests use `httptest` servers and interface fakes
  (`HardwareQuerier`, `RuleSetReader`).
