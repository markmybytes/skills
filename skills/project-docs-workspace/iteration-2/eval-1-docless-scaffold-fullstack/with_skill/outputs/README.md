# House730 內部工具庫 (House730 Internal Toolbox)

Internal web application for the House730 operations and marketing teams: dynamic ad
generation, bid campaign management, SEO competitive analysis, and web vitals
tracking, plus user, session, and access-log administration.

## Scope

An internal-only toolbox. Users are House730 staff; access is gated by
permission-based authorization (see `app/Enums/Permission.php`). There is no
public signup — accounts are provisioned by administrators and authenticated via
Google SSO.

## Stack

| Layer          | Technology                              |
| -------------- | --------------------------------------- |
| Backend        | PHP ^8.2, Laravel 12                    |
| Database       | MySQL (main app DB)                     |
| Frontend       | Vue 3 + TypeScript, Inertia.js          |
| Styling        | Tailwind CSS 4 + daisyUI                |
| Build          | Vite 7, `laravel-vite-plugin`           |
| Client routes  | Ziggy (`ziggy-js`)                      |

## Prerequisites

- PHP >= 8.2 (CI uses 8.4) with extensions for MySQL
- Composer
- Node.js 24 (pinned via `volta` in `package.json`)
- MySQL server
- Credentials for the external services listed in `.env.example`
  (House730 API and read-only House730 production DB, Google API for web
  vitals, Google OAuth for SSO, Ahrefs API for the SEO dashboard)

## Quick Start

```bash
composer install
npm ci
cp .env.example .env
php artisan key:generate
php artisan migrate --seed   # seeder only runs in local/preview environments
npm run dev                  # frontend dev server
```

Seed data is gated to `local`/`preview` environments. To promote a user to
administrator after setup:

```bash
php artisan auth:make-admin user@example.com
```

## Development

Run everything at once (Laravel server, queue worker, `pail` logs, Vite):

```bash
composer dev
```

| Command                    | Purpose                                        |
| -------------------------- | ---------------------------------------------- |
| `npm run dev`              | Vite dev server only                           |
| `php artisan serve`        | Laravel dev server                             |
| `php artisan pail`         | Tail logs                                      |
| `npm run build`            | Production build of frontend assets            |
| `npm run type-check`       | `vue-tsc` type check                           |
| `npm run lint` / `lint:fix`| ESLint over `resources/`                       |
| `npm run format`           | Prettier write; `format:check` to verify       |
| `vendor/bin/pint`          | PHP code style fixer (`pint --test` to verify) |

## Testing and Quality

```bash
composer run test   # config:clear + php artisan test (PHPUnit 11)
npm run test        # Vitest (resources/js/__tests__)
```

- **PHPUnit**: `tests/Feature` and `tests/Unit`; uses a separate MySQL test
  database `h730_toolbox_test` (see `phpunit.xml`).
- **Vitest**: jsdom environment, setup in `resources/js/__tests__/setup.ts`.
- **CI** (`.github/workflows/ci.yml`, PRs to `main`): Pint, ESLint, Prettier
  check, `vue-tsc` type check, Ziggy types staleness check, Vitest, frontend
  build, and the PHP test suite.

## Important Notes

- `resources/js/ziggy.d.ts` is generated by `php artisan ziggy:generate --types-only`
  and is committed; CI fails if it is stale.
- A queue worker is required — the `composer dev` script listens on the
  `default`, `dynamic-ad`, and `notification` queues.
- Scheduled jobs (web vitals fetching, dynamic ad file updates and purge) live
  in `routes/console.php`; run the scheduler via `php artisan schedule:work`
  (or cron) for them to fire.
- The dev-login routes (`/auth/dev`) exist only in `local`/`testing` environments.
- The application UI and locale default to Traditional Chinese (`zh_Hant_HK`).
