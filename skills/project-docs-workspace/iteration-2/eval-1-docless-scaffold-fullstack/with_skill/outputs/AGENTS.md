# AGENTS.md

Internal operations toolbox for House730 (Laravel 12 + Vue 3 / Inertia + TypeScript):
dynamic ads, bid campaigns, SEO dashboard, and web vitals tracking.

## Overview

- **Entry:** `public/index.php` → `bootstrap/app.php` → `routes/web.php` (Inertia renders Vue pages from `resources/js/Pages/`)
- **Run:** `composer dev` (Laravel server + queue worker + `pail` logs + Vite)
- **Processes:** database queue worker (`default`, `dynamic-ad`, `notification` queues) and the Laravel scheduler (web vitals fetch, dynamic ad jobs) defined in `routes/console.php`

## Tech Stack

- **PHP:** ^8.2, Laravel 12, Composer (CI runs 8.4)
- **Database:** MySQL — main app DB plus a read-only House730 production DB for property queries (`HOUSE730_DB_*` env vars)
- **Frontend/tooling:** Vue 3 + TypeScript, Inertia.js, Ziggy routes, Tailwind 4 + daisyUI, Vite 7; Node 24 via `volta`
- **Auth/authorization:** Google OAuth SSO; permission gates from `app/Enums/Permission.php` (`is_admin` bypasses all)
- **Other constraints:** default locale `zh_Hant_HK`; UI text is Traditional Chinese

## Repository Map

- `app/` — Laravel application code (controllers, models, jobs, services, enums)
- `app/Console/Commands/` — artisan commands (`auth:make-admin`, `restore:dynamic-ads`)
- `app/Services/` — business logic: House730 API client, web vitals providers, RSS, SEO, bid workflows
- `app/Jobs/` — queued work: web vitals fetch, dynamic ad file generation
- `routes/` — `web.php` (Inertia routes), `api.php`, `console.php` (schedules)
- `resources/js/` — Vue app: `Pages/`, `Components/`, `Layouts/`, `composables/`, `utils/`
- `resources/views/` — Blade layouts and email templates (`emails/`)
- `resources/js/__tests__/` — Vitest specs (setup in `vitest.config.ts`)
- `tests/Feature/` and `tests/Unit/` — PHPUnit suites
- `database/migrations/`, `database/seeders/`, `database/factories/` — schema and seed data (seeder gated to `local`/`preview`)
- `config/` — configuration; external services in `config/services.php`
- `.github/workflows/` — CI (`ci.yml`) and deployment (`deploy.yml`)

## Commands

Run from repository root. Apply fixes before verification.

| Scope         | Fix                              | Verify                                  |
| ------------- | -------------------------------- | --------------------------------------- |
| PHP style     | `vendor/bin/pint`                | `vendor/bin/pint --test`                |
| JS/Vue lint   | `npm run lint:fix`               | `npm run lint`                          |
| Formatting    | `npm run format`                 | `npm run format:check`                  |
| Type checking | —                                | `npm run type-check`                    |
| JS tests      | —                                | `npm run test` (Vitest)                 |
| PHP tests     | —                                | `composer run test` (PHPUnit)           |
| Build         | —                                | `npm run build`                         |

- `resources/js/ziggy.d.ts` is generated by `php artisan ziggy:generate --types-only` and is committed. Regenerate and commit it whenever routes change; CI fails if it is stale.
- `composer run test` clears config before running `php artisan test`.
- PHPUnit needs the `h730_toolbox_test` MySQL database (see `phpunit.xml`).

## Testing

- **PHPUnit (v11):** `tests/Feature/` and `tests/Unit/` — runner: `composer run test` or `php artisan test`
- **Vitest (v4):** `resources/js/__tests__/**/*.spec.ts` — jsdom, globals, setup file `resources/js/__tests__/setup.ts`; runner: `npm run test`
- **Fixtures/mocks:** test DB is MySQL (`h730_toolbox_test`); external API keys are dummy values in `phpunit.xml`
- **CI:** `.github/workflows/ci.yml` runs on PRs to `main` — Pint, ESLint, Prettier check, type check, Ziggy types staleness, Vitest, frontend build, then the PHP suite

## Boundaries

### Always

- Read the documentation map and relevant linked docs before making edits.
- Follow explicit user instruction over repository documentation when they conflict.
- Use the exact commands and prerequisites from the docs.
- Run relevant verification or tests before declaring work complete.
- Keep changes scoped and minimal.
- Preserve single sources of truth; update owning docs when behavior or interfaces change.
- Regenerate and commit `resources/js/ziggy.d.ts` when routes change.
- Preserve the `local`/`preview` gate on the database seeder and the `local`/`testing` gate on dev-login routes.

### Ask First

- Destructive, security-sensitive, or ambiguous changes.
- Changes touching the read-only House730 production DB connection or external API credentials.

### Never

- Commit secrets or local environment values.
- Hand-edit generated, vendored, or protected files.
- Add new permissions without updating `app/Enums/Permission.php` and its gates consistently.
