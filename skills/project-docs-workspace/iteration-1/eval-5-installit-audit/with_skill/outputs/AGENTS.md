## Project

Windows PC setup assistant / driver installer. Wails v2 desktop app: Go backend + Vue 3 frontend.

## Commands

```sh
# Dev (both Go + Vue hot-reload)
wails dev

# Build production binary
wails build

# Build with version stamp
wails build -ldflags "-X main.buildVersion=<version>"

# Go tests (CI scope: ./pkg/... — root app_test.go covers App methods only)
go test ./pkg/...

# Frontend tests
cd frontend && npm test

# Frontend lint + format
cd frontend && npm run lint
cd frontend && npm run format

# Frontend type-check only
cd frontend && npm run type-check
```

## Architecture

- **Go backend** (`main.go`, `app.go`, `pkg/`): Wails-bound structs exposed to frontend via `Bind`. Entry point is `main()` — it opens SQLite, runs migrations, applies staged updates, then starts Wails runtime.
- **Vue frontend** (`frontend/src/`): Pages, components, Pinia stores, composables, i18n. Uses Nuxt UI v4 + TailwindCSS v4.
- **Wails bridge** (`frontend/wailsjs/`): Auto-generated Go→JS bindings. **Do not edit** — regenerated by `wails dev` / `wails build`. ESLint and Prettier ignore this directory.
- **SQLite** (`pkg/storage/`): CGO-free driver (`glebarez/sqlite`). Schema migrations via `gormigrate/v2`. Baseline migration guards legacy installs.
- **App settings**: JSON file (`conf/setting.json`), not in SQLite. Uses `FileStore`/`MemoryStore`.
- **Updater** (`pkg/update/`): Native Go self-update using Windows file-rename trick. Python updater is a **separate repo** (`install-it-updater`) — don't look for it here.

## Key constraints

- **Windows-only app**: Go code uses Windows-specific APIs (file rename trick, WMI, WebView2). Build targets are x86 and x64.
- **CGO-free**: SQLite driver is pure Go. No CGO required for cross-compilation.
- **`init()` side effects**: `main.go` `init()` creates `conf/` and `drivers/` directories next to the binary. Root-level tests (`app_test.go`) note this is harmless.
- **`TriggerNativeUpdate` is untestable end-to-end**: It calls `os.Exit(0)`; only `extractZipToDir` is unit-tested.
- **Porter closes DB on import**: `porter.Porter` calls `db.Close()` before backup and `db.Reopen()` + `db.Migrate()` after import. If editing storage, account for this lifecycle.
- **Wails bindings must be in `Bind` list**: New Go structs exposed to frontend must be added to `Bind` in `main.go`. Enums go in `EnumBind`.

## Boundaries

### Always

- Read the documentation map and relevant linked docs before making edits.
- Follow explicit user instruction over repository documentation when they conflict.
- Use the exact commands and prerequisites from the docs.
- Run relevant verification or tests before declaring work complete.
- Keep changes scoped and minimal.
- Preserve single sources of truth; update owning docs when behavior or interfaces change.
- Run linters/formatters before manual style fixes: `npm run lint` / `npm run format` (frontend), `go fmt` / `go vet` (Go).

### Ask First

- Destructive, security-sensitive, or ambiguous changes.

### Never

- Commit secrets or local environment values.
- Hand-edit generated, vendored, or protected files: `frontend/wailsjs/**`, `vendor/**`, `node_modules/**`.
- Modify `.github/workflows/**` without explicit human instruction.

## CI

- **Test workflow** (`.github/workflows/test.yml`): Runs on PRs to `main`. Executes `go test ./pkg/...` on Windows and frontend `npm test` on Ubuntu.
- **Release workflow** (`.github/workflows/build_and_release.yml`): Triggered by `v*` tags. Builds x86 + x64 Windows binaries with UPX compression, bundles WebView2 runtime, downloads PCI ID database and PawnIO files, emits `.zip.sha256` checksums, builds Python updater from separate repo, drafts GitHub release.
